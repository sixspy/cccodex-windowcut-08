# 迟到归属册（不可混路径）

> 本表是迟到桶归属正确性的**唯一口径登记**。选定后当天禁止改口；任何偏离一律拒写并在审计记
> `late_attribution_drift`（归属偏了）。落库镜像见 `late_attribution_registry` 表（单行 `id=1`），
> 服务接口：`GET /api/late-attribution/registry`、`POST /api/late-attribution/choose`。

## 选定路径：甲（A）—— `window_id` 存活外键

- **登记日期**：2026-11-20（当天锁定，禁改口）
- **路径名**：`window_id_fk`
- **选定人**：system（本仓业务窗关账初始化时写入）

### 口径（只走这一条，不与乙混用）

1. `late_bucket.window_id` 为 `NOT NULL` 外键，`REFERENCES windows(id) ON DELETE RESTRICT`；
   连接统一 `PRAGMA foreign_keys=ON`。
2. 迟到入账（`ingest_svc`）必须带存活 `window_id`；写前经 `require_path_a` 守卫，归属册非 A 即拒写。
3. 删窗（`windows_svc.delete_window`）与桶生命周期**同事务**：
   - 仍挂桶行且无 `migrate_to`：拒删（409），窗与桶行原样保留；
   - 带 `migrate_to`：目标存活校验通过后，同事务级联改挂桶行再删窗；目标不存在/自迁等冲突整笔回滚；
   - 库层 `ON DELETE RESTRICT` 是第二道硬约束，绕过 API 裸删同样被 SQLite 拒绝。
4. 改挂桶行归属（`late_svc.reassign_bucket`）必须占桶锁 `late-bucket:{late_id}`；
   双人同改一桶，后到者 409、只记 `contention_log`，不写业务。
5. 写事务统一 `BEGIN IMMEDIATE` 且 `busy_timeout=0`：写锁入口即定，后到立即 `SQLITE_BUSY` → 409 争用，
   不排队、不串行化“看似成功”。
6. 旧库（仅 `window_name`）挂卷升级：能按名匹配存活窗的回填 `window_id`；匹配不上的整笔转入
   `late_bucket_quarantine` 检疫，可核证、不丢、不按同名串并。

### 明确不采用的乙路径（B）—— 窗名快照强制复检

- 桶行存 `window_name_snapshot`，对账时强制复检现窗名，不一致整笔拒绝汇总。
- 本仓**不实现、不接受当天切换**；`POST /api/late-attribution/choose {"path":"B"}` 当天返回 409 并记归属偏了。
- 仅跨日才可在登记册改口（保留纪律），但乙路径写实现不存在，切到 B 后所有桶写路径会被 `require_path_a` 拒写。

## 五处同态（同一来源 `late_bucket.window_id`）

| 面 | 接口/位置 | 口径 |
|----|-----------|------|
| 迟到明细 | `GET /api/late-bucket` | JOIN 存活窗，带 `window_id` + `window_name_live` |
| 汇总卡 | `GET /api/late-bucket/summary` | `GROUP BY window_id`，附 `orphan_buckets`/`quarantined_buckets` |
| 窗口条带 | `GET /api/windows` | 每窗 `late_bucket_count` 子查询 |
| 对账迟到计数 | `GET /api/reconcile`、`/api/reconcile/{wid}` | `WHERE window_id=?`，单窗与总览同口径 |
| 审计 | `audit_trail` | `ingest_late`/`late_reassign`/`late_bucket_migrate` 载荷均带 `window_id` |

终态不变量：`orphan_buckets = 0`（检疫行不计入任何窗），明细总数 = 汇总各窗笔数之和 + 孤儿数。
